Host Drive Lock & Safety Isolation

L155A cross-verifies drive hardware bus topology (`USBSTOR`, `NVMe-over-PCIe`, `SCSI`). Internal boot drives, recovery partitions, and BitLocker-encrypted volumes are cryptographically excluded from the destination roster.

  • ✓ Kernel-level device exclusion list
  • ✓ Lock volume handles via FSCTL_LOCK_VOLUME
  • ✓ Prevent Windows OS unmount crashes
daemon/guard.rs — Host Filter 
pub fn validate_target_bus(target: &Device) -> Result<DriveSafe> {
    if target.is_system_boot() || target.has_active_pagefile() {
        return Err(SecurityViolation::HostProtected);
    }
    target.acquire_exclusive_lock()?;
    Ok(DriveSafe::Isolated)
}

Guaranteed UEFI ESP Boot Partition

Older ISO images lack compliant EFI system partitions for modern Secure Boot setups. L155A automatically constructs a dedicated FAT32 ESP stub containing signed EFI bootloaders (`BOOTX64.EFI`), maintaining boot compliance across all motherboard firmware.

  • ✓ Native UEFI Class 3 & CSM backward compatibility
  • ✓ Automatic 100MB ESP boundary carving
  • ✓ Secure Boot certificate validation

    206847
)?;
esp.format_fat32_volume("ESP_L155A")?;
esp.inject_efi_stub(&signed_bootloader)?;

Direct Unbuffered DMA Writes

Windows writes files through system file cache buffers that frequently choke on sustained gigabyte transfers. L155A initiates `FILE_FLAG_NO_BUFFERING` and `FILE_FLAG_WRITE_THROUGH` sector pipelines directly into the USB controller's internal buffer.

  • ✓ Zero memory allocation stall in host OS
  • ✓ Consistent 120+ MB/s writes on USB 3.2 Gen 2
  • ✓ Real-time CRC32 streaming parity
io/dma_writer.rs 
let flags = FILE_FLAG_NO_BUFFERING | FILE_FLAG_WRITE_THROUGH;
let handle = open_physical_drive(drive_id, flags)?;
while let Some(chunk) = stream.next_chunk() {
    handle.write_aligned_sector(chunk)?;
    telemetry.update_rate(chunk.len());
}
